# simipix

**simipix** — локальный визуальный поиск изображений на **DINOv2-giant** (`facebook/dinov2-giant`, 1536-мерные эмбеддинги) + **LanceDB**. Поиск по картинке, лицу, позе, цветовой палитре и NSFW-контенту. Тяжелые веса локально, дедуп по sha1, защита от перемещения файлов. Веб-страница: каталог, текстовый фильтр и пагинация, client-side cosine-поиск похожих снимков, топ-5 палитры и позы.


## Установка

```bash
pip install .
# или зависимости для разработки:
pip install -r requirements.txt
```

## Быстрый старт

```bash
# 1) Загрузить веса модели локально (offline-режим, ~2.5 ГБ)
python download_model.py --out ./models

# 2) Проиндексировать каталог изображений
imgsim index ./photos --db ./image_db --model-dir ./models

# 3) Найти похожие на изображение
imgsim search ./sample.jpg --db ./image_db --model-dir ./models --top 50

# 4) Статистика индекса
imgsim stats --db ./image_db

# 5) Открыть страницу с каталогом индекса и поиском
imgsim browse --db ./image_db
```

## Команды

| команда | что делает |
|---------|------------|
| `index <каталог>` | обход каталога, векторизация, дедупликация |
| `search <файл>` | поиск похожих, генерация HTML-галереи в `results/` |
| `stats` | число записей, размерность, тип ANN-индекса |
| `browse` | страница-HTML: каталог всех записей + поиск по имени/путю и «похожие» (cosine в браузере) |
| `find_duplicates` | найти визуальные дубликаты, сгенерировать HTML для удаления (чекбоксы + rm-команды) |
| `graph` | граф сходства: Louvain-кластеры, хабы, аномалии — HTML-визуализация (vis.js) + JSON |
| `delete <хеш...>` | удалить записи из индекса по хешу (только по команде) |

### Ключи `index`

- `--db` — каталог базы LanceDB (по умолчанию `./image_db`)
- `--model-dir` — локальные веса модели (по умолчанию — с HuggingFace Hub)
- `--batch` — размер батча (GPU: 16, CPU: 4)
- `--no-recursive` — не заходить в подкаталоги
- `--rebuild` — пересоздать таблицу с нуля
- `--prune` — удалить записи о несуществующих файлах
- `--max-side` — сжатие перед векторизацией, px (по умол. 1024)

### Ключи `search`

- `--db`, `--model-dir`, `--top` (по умол. 50), `--min-score` (0..1),
  `--out` (путь к HTML), `--max-side`, `--mode` (`image` / `face` / `pose` /
  `palette`): `palette` — поиск по цветовой палитре (домантные цвета),
  тяжёлая модель DINOv2 в этом режиме не грузится.

### Ключи `browse`

- `--db`, `--model-dir` — как у других команд
- `--top` — сколько похожих показать на карточке (по умол. 10)
- `--out` — путь к HTML-странице (по умолчанию `results/browse_<время>.html`)

Страница самодостаточная: открывается на любой машине, поиск по индексе
требует только её, без доступа к базе. «Похожие» вычисляются в браузере по
встроенным векторам (до 300 записей; больше — только текстовый фильтр). В
выпадающем «Похожие» выберите режим: `изображения` / `позы` / `лица` — поиск
по вектору модели, позе (DW-Pose) или лицу. Режимы «позы» и «лица» доступны
только на малых каталогах, когда вектора встроены в страницу.
Все миниатюры встроены в HTML как base64 (data URI) — страница не зависит от
файлов на диске и открывается где угодно.

### Ключи `find_duplicates`

- `--db`, `--model-dir` — как у других команд
- `--threshold` — порог cosine-схожести для дубля, 0..1 (по умол. 0.85)
- `--out` — путь к HTML-отчёту (по умолчанию `results/duplicates_<время>.html`)

Генерирует HTML-отчёт (как VisionEmbed-CLI/find_duplicates.py): группы
похожих изображений с миниатюрами, чекбоксами и кнопкой «Удалить отмеченное».
Кнопка **не удаляет** — она собирает `imgsim delete <хеш>` + `rm <путь>` и
показывает их в поле, чтобы вы проверили и запустили вручную. Дубликаты по
ОДНОМУ содержимому во время индексации уже сливаются в одну запись, поэтому
`find_duplicates` ищет ВИЗУАЛЬНЫЕ дубликаты — разные файлы, похожие картинки.

### Ключи `graph`

- `--db`, `--model-dir` — как у других команд
- `--threshold` — порог cosine-схожести для рёбра, 0..1 (по умол. 0.85)
- `--out` — путь к HTML (по умолчанию `results/graph_<время>.html`); рядом лежит `.json`

Строит неориентированный граф над сохранёнными L2-нормированными векторами
DINOv2: узлы — записи, рёбра — пары с cosine ≥ threshold (вектора уже
нормированы, поэтому cosine ≈ скалярное произведение — перевычисление не нужно).
Затем Louvain-кластеризация (мягкие сообществa «фотосессий/объектов», в отличие
от жёсткого порога `find_duplicates`), центральность по степени (хабы — мастер-
файлы с кропами/водяными знаками; аномалии — изолированные узлы) и транзитивный
поиск вглубь. Вывод: `graph.json` (полные данные: узлы, рёбра, кластеры, хабы,
аномалии) и `graph.html` — интерактивный граф (vis-network через CDN, без локального
фронта). Офлайн, без LLM-токенов.

### Ключи `delete`

- `--db`, `--model-dir` — как у других команд
- `hashes [hashes ...]` — хеши записей к удалению

Удаляет выбранные записи из индекса. Несуществующие хеши игнорируются. После
удаления файлов пересобрать индекс: `imgsim index <каталог> --db <db> --prune`.

## Как это работает

- **Модель.** DINOv2-giant, 1536-мерные эмбеддинги (CLS-токен, L2-нормализованный).
  fp16 на CUDA, fp32 на CPU.
- **Хранение.** Одна таблица `images_giant` в LanceDB. До 100 000 строк —
  точный плоский поиск, после — автоматически строится IVF-PQ (cosine).
- **Дедупликация по хешу.** Первичный ключ записи — `sha1` содержимого файла.
  Две одинаковых картинки (в т.ч. скопированные) хранятся как одна запись,
  вектор вычисляется один раз.
- **Защита от переименования и перемещения.** Запись хранится по хешу, а не
  по пути. Если файл переместили или переименовали — при следующей индексации
  путь/время модификации обновляются, дубль не создаётся.
- **Миниатюры.** Один файл WebP на уникальный контент (`<db>/thumbs`),
  имя = хеш. Участвуют в HTML-галерее.
- **Палитра и контент.** Каждая запись хранит до 20 домантных цветов
  (`palette`, JSON: hex/rgb/доля %) и классификацию контента (`content`,
  JSON: safe/nsfw по `Falconsai/nsfw_image_detection`). Палитра нужна для
  поиска `search --mode palette`; в каталоге (`browse`) цвета показываются
  полоской, тип контента — бейжем. Анализ ленивый, модели грузятся один раз.

## Защита от аномалий

- Файлы больше 512 МБ пропускаются.
- Битые/нечитаемые файлы не ломают индексацию (учитываются как ошибки).
- При нехватке памяти батч автоматически уменьшается вдвое.
